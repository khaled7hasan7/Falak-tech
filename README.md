# لوحة فلك — Falak Console

الجهة البائعة من نظام الاشتراك. تعمل على جهازك أنت، ولا تُنصَّب عند أي عميل.

```bash
start.bat
```

ثم افتح <http://127.0.0.1:8787>.

---

## لماذا هي خارج مجلد المشروع؟

`deploy/update.sh` يسحب `origin/main` إلى خوادم العملاء. أي ملف داخل مستودع
NexoPOS ينتهي به المطاف على قرص عميل — بما في ذلك أي صفحة تُصدر التراخيص.

هذه اللوحة تحمل **المفتاح الخاص** الذي يوقّع كل ترخيص تبيعه. لذلك تعيش في
`C:\project\falak-console`، خارج المستودع تماماً، ولا يصل إليها `git` من هناك.

---

## أول تشغيل

يطلب منك أمرين مرة واحدة:

1. **كلمة مرور للوحة.** اللوحة مربوطة بـ `127.0.0.1` فلا تصلها الشبكة، لكن من
   يجلس على جهازك يصلها. كلمة المرور هي ما يمنع ذلك.
2. **مفتاح التوقيع.** إن كنت قد أصدرت تراخيص من قبل — وقد فعلت — **استورد
   مفتاحك القديم**، لا تولّد جديداً. مكانه:

   ```
   C:\project\NexoPOS-master\NexoPOS-master\storage\app\falak-license-private.key
   ```

   افتحه، وانسخ محتواه، والصقه في خانة «المفتاح الخاص».

   توليد مفتاح جديد **يُبطل كل ترخيص أصدرته بالقديم**، ولا حلّ بعدها إلا زيارة
   كل عميل وتغيير مفتاحه العام يدوياً.

## دورة العمل

### عميل جديد

1. **محل جديد** — اسمه، البلدة، الهاتف. سجّله حتى قبل أن تعرف معرّف تنصيبه.
2. ضع مفتاحك العام في ملف `.env` عنده. السطر جاهز في صفحة **مفتاح التوقيع**:

   ```
   FALAK_LICENSE_KEY=...
   FALAK_VENDOR_NAME=Falak
   FALAK_VENDOR_PHONE=+970 5X XXX XXXX
   ```

   بدون `FALAK_LICENSE_KEY` **لا توجد بوابة اشتراك أصلاً** والنظام يعمل بلا قيد.
   هذا أكثر خطأ يُنسى عند أول تركيب.

3. العميل يفتح النظام فيرى شاشة الاشتراك، وعليها معرّف تنصيبه — `XXXX-XXXX-XXXX`.
   يقرؤه لك في الهاتف.
4. افتح صفحته هنا، اكتب المعرّف، اختر المدة، **وقّع المفتاح**.
5. **إرسال على واتساب** — يفتح محادثته برسالة جاهزة فيها المفتاح وطريقة تركيبه.
6. يلصقه في **الإعدادات ← النظام ← الاشتراك** ويضغط تفعيل.

### تجديد

نفس الصفحة، نفس الزر. والافتراضي أن الاشتراك الجديد **يبدأ من نهاية الحالي**،
فالتجديد المبكر لا يُضيّع على العميل أياماً دفع ثمنها.

### «المفتاح لا يعمل عنده»

صفحة **فحص مفتاح**: الصقه كما وصل العميل. تخبرك أيّ الثلاثة هو:

| ما تقوله الصفحة | المعنى |
|---|---|
| الصيغة غير صحيحة | وصل ناقصاً — النسخ قطعه. أعد إرساله. |
| التوقيع لا يطابق مفتاحك | ليس مفتاحاً منك، أو عُدِّل. |
| التوقيع صحيح + تنصيب مختلف | المعرّف الذي أخذته بالهاتف غلط. أعد الإصدار. |

## الحالات على الشاشة

| | |
|---|---|
| **ساري** | مدفوع وسليم |
| **ينتهي قريباً** | آخر ١٤ يوماً — العميل يرى تنبيهاً وما زال يعمل |
| **مهلة سماح** | انتهى، وما زال يعمل ٧ أيام إضافية |
| **مقفل** | انتهت المهلة — النظام متوقف عنده |

هذه العتبات هي نفسها في `config/falak.php` عند العميل، فما تقرؤه هنا هو ما يراه هو.

## المفتاح الخاص

في `data/private.key`. ٦٤ بايت. هو كامل قيمة المنتج.

- **خذ منه نسخة احتياطية خارج هذا الجهاز.** فقدانه = لا تجديد لأي عميل بعد اليوم.
- **لا ترفعه على git ولا تضعه على جهاز عميل.** تسريبه = أي شخص يُصدر تراخيص
  مجانية باسمك، بلا طريقة لإبطالها عن بُعد.

مجلد `data/` كامل مستثنى من git. إن أردت وضعه على قرص مشفّر أو ذاكرة USB:

```bash
FALAK_DATA_DIR=E:/falak-data start.sh
```

## تفاصيل تقنية

- PHP ‎8.1+‎ مع `sodium` و`pdo_sqlite`. لا composer ولا أي حزمة خارجية.
- التوقيع Ed25519. الترخيص: `FALAK1.<base64url(payload)>.<base64url(signature)>`
- **صيغة الترخيص مطابقة تماماً** لـ `app/Console/Commands/FalakLicenseIssueCommand.php`
  في المنتج — نفس المفاتيح، نفس ترتيبها، نفس أعلام JSON. التوقيع يغطي البايتات
  المُرمَّزة، فأي اختلاف في الترتيب يُنتج تراخيص يرفضها `FalakLicenseService`
  عند العميل باعتبارها مزوّرة. **إن غيّرت طرفاً فغيّر الآخر.**
- `php artisan falak:license-issue` ما زال يعمل كما هو؛ اللوحة واجهة له، لا بديل.
- السجلّ في `data/console.sqlite` — كل ترخيص وُقّع يوماً ما محفوظ فيه.
